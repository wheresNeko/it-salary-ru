## 摘要

本项目研究的问题是：俄罗斯 IT 就业市场中，哪些因素决定薪资水平？能否从岗位文本和结构化属性中准确预测薪资？

工作严格遵循四段流程 —— 数据挖掘、数据处理、预测分析、验证 —— 数据来自 Трудвсем（«Работа России»，俄罗斯国家就业门户）的官方开放数据，共 22,387 条岗位记录。

有三个结论值得先讲清楚。

**最有价值的产出不是模型，而是一组缺陷。** 我们找到并量化了四个数据问题，其中三个是**静默失效**的：一个用字面零值 `0` 表示"薪资未指定"的哨兵值；一个文档标注为整数、实际是未公开编码、最终必须从特征集中撤除的字段；以及一个让朴素正则**漏掉 43% 的 C++ 岗位**的西里尔/拉丁字母混淆。每一个都会产出看起来合理、实则错误的答案。

**在这个数据集上，神经网络不能自我辩护。** 在**逐字节相同的输入**下，梯度提升达到 R² = 0.615，而多层感知机是 0.595，且在全部 7 个随机种子上都落败。

**控制变量后 IT 溢价基本消失。** IT 与对照组的中位数原始差距是 5,000 卢布（11.1%）；在控制地区、学历、职业和技能特征后，估计溢价为 **+1.0%**。

## 1. 研究问题

> 俄罗斯 IT 就业市场中，哪些因素决定薪资水平？能否仅从岗位文本和结构化属性中准确预测薪资？

三个子问题构成工作骨架：

1. 薪资信号有多少来自结构化属性，多少来自自由文本？而门户不提供结构化技能字段，必须从文本中挖掘多少信息？
2. 在控制地区和学历后，IT 岗位相对其他行业的薪资溢价有多大？
3. 预测精度是否值得使用神经网络，还是更简单的模型表现相同？

子问题 3 是刻意设计成**可证伪**的。答案在 §4.2，结论是"不值得"。

## 2. 数据源

### 2.1 第一个候选源已经被关闭

最显而易见、也是最初选定的数据源是 hh.ru —— 俄罗斯最大的招聘网站。**它已无法用于此目的。** 自 2026 年 4 月起，hh.ru 关闭了公开的岗位搜索接口：未授权请求访问 `GET /vacancies` 一律返回 `403 Forbidden`，密钥只发给通过审核的认证雇主和招聘服务商。

这一点是**直接实测**确认的，不是读到别人这么说：

| 端点 | 结果 |
|---|---|
| `hh.ru /areas` | **200**（2,425,807 字节） |
| `hh.ru /professional_roles` | **200**（53,921 字节） |
| `hh.ru /vacancies` | **403 Forbidden** |
| `hh.ru /vacancies/{id}` | **403 Forbidden** |
| `hh.ru /employers` | **403 Forbidden** |

这是**端点级授权**，不是网络或请求头问题：参考类端点正常应答，而所有返回岗位记录的端点全部被拒。这件事的意义超出本项目本身 —— 任何依赖爬取大型商业招聘网站的设计，在法律和技术上都站不稳；而开放数据的复用授权是明确的。

### 2.2 替代方案

Трудвсем 是俄罗斯国家就业门户，由 Роструд 运营。它的岗位 API 不需要密钥、不需要注册、不需要审核，数据作为官方开放数据发布。

| 属性 | 值 |
|---|---|
| 端点 | `https://opendata.trudvsem.ru/api/v1/vacancies` |
| 认证 | 不需要 |
| 每条记录字段数 | 31 |
| 采集时全国总量 | 522,303 个岗位 |
| 许可 | 官方开放数据（见 [LICENSE](../LICENSE)） |

门户不提供职业类别筛选，所以 IT 子集通过 `text=` 关键词与 `region_code` 交叉切片获得。

### 2.3 采集，以及采集约束意味着什么

在大规模采集之前先逆向了 API 的行为，因为它的三个特性决定了什么做法可行。三者都有可复现的探测脚本记录在 `stage0_source_verification/probes/`。

**未知参数名被静默忽略。** `regionCode`、`regionId`、`area`、`regionName` 全部返回**全国数据**、HTTP 200、没有任何警告。正确的名字是 `region_code`。不校验返回 `region.name` 的客户端，会在"以为筛了地区"的情况下拿全国数据训练模型；本采集器对每次请求都断言返回的地区名。

**分页在调查期间失效了。** 早期 `offset` 最深可用到 999；现在 `offset > 0` 一律返回 HTTP 200 但**零条记录**。因此覆盖率只能靠**切片查询**扩展，绝不靠分页，且每个（关键词 × 地区）单元格上限 100 条。

**服务端每次请求耗时 5–6 秒**，且连接池无帮助 —— 瓶颈是服务端处理。并发确实有效，而且是**实测**而非假设：4 个 worker 达到 0.56 req/s，8 个达到 1.20 req/s，零失败。采集器用 8 个，这是把采集从 8 小时压到 24.7 分钟的唯一办法。

最终结果是 2,002 次请求产出 **22,387 条记录** —— 12,656 条 IT + 9,731 条非 IT 对照组 —— 覆盖 89 个地区，另有通过探测 1–92 号编码实测得出的 78 个地区目录（而非硬编码）。

**这些约束是采样方法，不只是实现细节。** 单次查询内 API 返回它自己的排序，偏重新近发布，但既不随机也未排序。所以这批数据是**便利样本**，不是概率样本，本报告中的每一个估计描述的都是这个样本。

## 3. 方法

### 3.1 加工：两处修复、一处撤除

Stage 2 把 22,387 条原始记录变成 19,578 × 72 的分析表。其中四个决策改变了数据的含义，四者都被**记录在案**而非静默执行。

**重复。** 446 条记录出现在多个关键词下（同一岗位同时命中 IT 与对照词）。它们被折叠进 IT 组，使两组互斥 —— 否则"IT 溢价"会变成部分自己和自己比。另有 2,363 条近重复（同雇主、同规范化标题、同薪资的重复投放）被折叠为最新的一份。

**零值哨兵。** 门户用**字面值 `0`** 表示"薪资未指定"（原文 `"от 0"`），而不是留空。涉及 179 条记录。**看起来像真数据的哨兵值是最危险的一类缺陷**：`log(0)` 是 `-inf`，模型会认真地从"0 卢布月薪"里学习。这些记录被置为缺失并打上标记。

**退化区间。** 21,941 条有薪资的记录里，自由文本 `salary` **100% 是 `"от N"` 形式**，所以文本从不携带上界。当 `salary_max <= salary_min` 时（占全表 38.5%），区间不含信息量，于是 `salary_max` 置为缺失并给该行打标记。原始值被保留，以便日后评估不同策略而无需重新采集。

**一个必须撤除的字段。** `requirement.experience` 文档标注为整数、读起来像年数。**两者都不是。** 实测取值空间是 `0,1,2,3,4,5,6,7,10,18,20,21,23,31,42`，无公开刻度；与自由文本交叉验证即可定论：`code = 0` 的广告要求**最高 35 年**经验，所以 `0` 不可能表示"无经验要求"；`code = 10` 出现在写着"от 10 лет"的广告上，而 `code = 18` 出现在写着"от 1 года"的。该列作为不透明编码保留供审计，**从特征集中撤除**。因此经验在本数据源上不是可用变量。

### 3.2 文本挖掘，以及字母表为什么重要

结构化 `skills` 字段在 **77.4%** 的记录里为空，所以技术特征必须从俄语自由文本中挖掘：24.1% 的记录有结构化技能，而 RegEx 能从 36.7% 的记录中挖出至少一个技能。

**朴素做法会静默失败。** 俄语广告经常用**西里尔字母 С**（U+0421）写 `C++` 和 `C#`，它与拉丁 C 视觉上完全相同，而 Python 的 `re.IGNORECASE` **不会**跨字母表折叠：

```python
re.search(r"c\+\+", "C++", re.I)   # -> 匹配
re.search(r"c\+\+", "С++", re.I)   # -> None    静默漏掉
```

全语料实测：137 个岗位只用拉丁写法，**102 个只用西里尔写法**，100 个两种混用。朴素正则的漏检率是 **102/239 = 43%**。

**看似显然的修法 —— 归一化整段文本 —— 会破坏正常俄语**：`с` 是俄语最常用的介词之一，`Р`、`О`、`А` 也是极常见字母。所以我们让**模式本身**在真正发生混淆的少数位置接受两种字母，并用显式左边界锚定，使其无法从俄语单词内部命中。有一项测试断言 `"Работа с детьми"` 不产出任何技术项。

### 3.3 建模

**切分是时序的，不是随机的。** 训练集是 2026-08-20 之前发布的 14,513 条，测试集是之后的 4,886 条。随机切分有两重无效性：雇主会重复投放同一广告，近重复能躲过 Stage 2 的去重而散落两侧；而且样本偏重新近发布，随机切分是让模型在时期内插值，而非向前外推。

**四类模型，受控输入。** 使用两种特征设计：稀疏设计（one-hot + 完整 TF-IDF 词表）给线性模型；稠密设计（one-hot + 数值 + 技能标记 + 同一 TF-IDF 的截断 SVD 压缩）由三个模型**逐字节共享**。M1b、M2、M3 拿到完全相同的矩阵，这正是让对比成为**模型类别**对比而非特征工程对比的关键。

**泄漏审计在设计上就是穷尽的。** 目标是 `log(salary_min)`。表里每一列都必须携带显式决策 —— 特征、文本来源、目标派生、或带理由排除 —— 有一列没有决策，测试就失败。这一点至关重要，因为 `salary_text` **字面上就是 `"от <目标值>"`**；它会产出近乎完美且完全无意义的模型。另有一项测试把已知危险列名钉为泄漏，所以审计**无法靠"删掉声明"而非"分类列"来通过**。

### 3.4 验证

**103 项测试、约 16 秒、不需要网络**，每次 push 由 CI 在 Python 3.12 和 3.13 上强制执行。其中**四个接缝**承载关于数据的论断 —— 解析函数、修复策略、泄漏不变量、端到端路径 —— 接缝在写任何测试之前就已确认；第五个文件检查每份文档里的每个相对链接是否仍能解析，那属于仓库卫生而非关于数据的论断。测试抓出两个真 bug 并逼出一处接口改进，三者都记录在验证报告里。

## 4. 结果

### 4.1 数据实际是什么样

| 测量项 | 值 |
|---|---:|
| 原始记录 | 22,387 |
| 分析表 | 19,578 行 × 72 列 |
| 薪资可用 | 99.09% |
| 零值哨兵（`"от 0"`） | 179（0.91%） |
| `salary_max == salary_min` | 有上下界的记录中占 35.8% |
| `skills` 字段为空 | 77.4% |
| C++ 的西里尔字母漏检率 | **43%** |
| 质量门禁通过 | **10/10** |

薪资分布严重右偏 —— 中位数 47,000 卢布，而 99 分位是 200,000 —— 这是目标在对数尺度上建模的原因。

### 4.2 模型对比

所有模型在同一时序留出集上评估。MAE 在指数还原回原尺度后以卢布计；测试集中位薪资为 49,999 卢布。

| 模型 | MAE（卢布） | 占中位数 | 中位绝对误差 | R²（log） |
|---|---:|---:|---:|---:|
| M0a 全局训练中位数 | 28,594 | 57.2% | 15,000 | −0.177 |
| M0b（地区 × 学历）格中位数 | 23,674 | 47.3% | 12,668 | 0.187 |
| M1 Ridge —— 稀疏，完整 TF-IDF | 17,966 | 35.9% | 10,224 | 0.592 |
| M1b Ridge —— 稠密设计 | 18,264 | 36.5% | 10,402 | 0.588 |
| **M2 梯度提升 —— 稠密** | **17,478** | **35.0%** | **9,692** | **0.615** |
| M3 神经网络（MLP）—— 稠密 | 17,945 | 35.9% | 10,032 | 0.595 |

最佳学习模型比最强基线改善 **26.2%**。

**子问题 3 的答案：不值得，神经网络不能自我辩护。** M2 与 M3 输入相同，唯一差别是模型类别。MLP 的 MAE 差 2.7%，R² 低 0.020。

单个随机种子对神经网络不算证据，所以 MLP 用 **7 个种子**重训：R² = 0.6002 ± 0.0038（范围 0.595–0.605）。**M2 在全部 7 个种子上、两个指标上都胜出。** 诚实的表述是：梯度提升赢的幅度约等于网络自身的种子噪声宽度 —— 它不是以某种压倒性优势取胜。**神经网络真正失败的，是提供任何超出该噪声的收益**，同时付出可解释性和调参成本。

从稠密设计换到完整 TF-IDF 词表（M1b → M1）值 1.6% 的 MAE，这就是文本挖掘可测量的贡献。

### 4.3 控制变量后 IT 溢价基本消失

Stage 2 报告的原始差距是：IT 中位数 50,000 卢布，对照组 45,000，**相差 11.1%**。

这不是受控对比 —— IT 岗位集中在莫斯科和圣彼得堡，且集中在更高学历的职业中。把 `is_it` 指示变量放进 Ridge 回归，与地区、学历、职业、工作制和技能特征并列：

- `is_it` 的系数（对数尺度）：**+0.0103**
- 控制其他变量后的隐含薪资溢价：**+1.0%**

**所以原始差距几乎完全是构成差异，不是溢价。** 剩下的 1% 应理解为**偏相关**而非因果效应：控制变量仅限于本数据集测量到的内容，未测量的差异（资历、合同类型、雇主性质）依然存在。

### 4.4 模型实际在用什么

M2 的置换重要性，在 3,000 条测试样本上测得：

| 排名 | 特征 | 打乱后 MAE 增量 |
|---:|---|---:|
| 1 | `region_name_Город Москва` | 0.0362 |
| 2 | `lng` | 0.0287 |
| 3 | `lat` | 0.0213 |
| 4 | `specialisation_Образование, наука` | 0.0145 |
| 5 | `svd_17`（文本成分） | 0.0131 |
| 6 | `schedule_Неполный рабочий день` | 0.0114 |

**地理位置占主导**，而文本是通过 SVD 成分而非任何单个技能标记发挥作用的。这既是对模型的发现，也是对俄罗斯劳动力市场的发现：**岗位在哪，比岗位要求什么更重要。**

### 4.5 误差分析，以及一处系统性偏差

| 子群体 | 行数 | MAE（卢布） | 偏差（卢布） |
|---|---:|---:|---:|
| IT | 3,015 | 19,206 | −7,792 |
| 对照组 | 1,871 | 14,694 | −5,519 |
| `salary_open_ended` = False | 2,886 | 14,665 | −4,026 |
| `salary_open_ended` = True | 2,000 | 21,536 | −11,100 |
| 地区：Город Москва | 458 | 41,657 | −21,776 |
| 地区：Город Санкт-Петербург | 323 | 27,256 | −14,857 |

两点值得注意。

**莫斯科是迄今最难的子群体** —— MAE 41,657 卢布，是总体数字的两倍。首都的薪资离散度很大，而模型的特征无法解释它。

**所有子群体的偏差都是负的**，加权平均约 **−6,900 卢布**（中位数的 13.8%）。这不是某个子群体的假象，而是建模选择的已知后果：对 `log(salary)` 拟合平方误差估计的是**对数的**条件均值，指数还原后得到的是条件**中位数**。对右偏分布而言中位数低于均值，所以预测系统性偏低。标准修正方法是 **Duan smearing 估计量**，或在原尺度上指定损失函数；本报告两者都未采用，这一省略是被**记录**的，而不是被掩盖的。

## 5. 讨论

**流程的第四段证明了它的价值。** §3.1 和 §3.2 中的缺陷不是靠盯着模型发现的，而是靠**把数据当作需要被证伪的对象**发现的。三个静默缺陷中有两个只能通过查看真实记录发现：读多少文档都不会告诉你俄语广告用另一个字母表拼写 C++，也没有任何类型标注会告诉你一个"整数"字段其实是不透明编码。

**关于神经网络的否定结论本身就是一个结论。** 换个更大的网络、报一个略好的数字，是最省事的路。但我们把对比设计成**答案可以朝任一方向出来**：相同输入，加上与网络自身方差相称的种子扫描。在这个规模和形态的表格数据上，额外的容量买不到任何可测量的东西。

**控制构成差异改变了叙事。** "IT 溢价主要是地理与职业构成"这个结论，比它所取代的原始差距更有意思，而且只有多变量模型才能支撑这类论断。

## 6. 局限

1. **样本不是随机的。** 单次查询内 API 返回它自己的排序，且每个（关键词 × 地区）单元格上限 100 条。所有估计描述的是这个样本，不是俄罗斯岗位总体。
2. **门户偏向国企和蓝领岗位。** IT 只占 52.2 万全国岗位中的少数。模型只在它被拟合的人群内有效。
3. **`salary_max` 在 38.5% 的记录中不可用**，且自由文本薪资从不携带上界。只对 `salary_min` 建模。
4. **经验不可用。** `requirement.experience` 是未公开编码，而自由文本只在少数广告中声明经验要求。
5. **技能抽取基于字典。** 不在模式里的技术就是不可见的，没有任何测试能发现缺失的条目。
6. **IT 溢价是偏相关，不是因果效应。**
7. **预测系统性偏低**约 13.8%，原因见 §4.5。
8. **未做超参数搜索。** 模型使用合理的默认值，所以对比是**模型类别之间**的对比，而非调优实例之间的对比。
