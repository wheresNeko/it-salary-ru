# 基于俄罗斯国家就业开放数据的 IT 岗位薪资预测

**本项目发现了什么。** 本文档回答研究问题；数据源、流水线与复现方式在 [README](../README.md)，各阶段报告的完整细节见 §6。

*English: [final_report.md](final_report.md)*

---

## 摘要

> **俄罗斯 IT 就业市场中，哪些因素决定薪资水平？能否从岗位文本和结构化属性中准确预测薪资？**

**岗位在哪，比岗位要求什么更重要。** 地理位置是最强的预测因子，且优势明显 —— 莫斯科指示变量排第一，经纬度排第二、第三 —— 其次是职业，再次是工作制。自由文本有贡献，但是通过**学习到的成分**而非任何单个具名技能。

**控制这些因素后，"是 IT 岗位"几乎不值钱。** IT 与对照组中位数的原始差距是 11.1%；在控制地区、学历、职业和技能后降到 **+1.0%**。表面上的溢价其实是**构成差异**：IT 岗位集中在薪资本来就高的地方。

**典型薪资的三分之一就是典型误差。** MAE 为 17,478 卢布，中位薪资 49,999 卢布 —— 占 **35.0%**，R² = 0.615，且是在**向前外推**的时序留出集上。这个精度足以描述一个市场，不足以给单个 offer 定价。

**神经网络不能自我辩护。** 在逐字节相同的输入下，梯度提升 0.615，MLP 0.595，且在全部 7 个种子上都胜出。

## 1. 研究问题

主问题见上方。三个子问题构成工作骨架，各自在 §2 回答。

| | 子问题 | 回答位置 |
|---|---|---|
| **Q1** | 薪资信号有多少来自结构化属性、多少来自自由文本？门户不提供结构化技能字段，必须从文本中挖掘多少？ | §2.3 |
| **Q2** | 控制地区和学历后，IT 岗位的薪资溢价有多大？ | §2.4 |
| **Q3** | 预测精度是否值得使用神经网络，还是更简单的模型表现相同？ | §2.5 |

Q3 是刻意设计成**可证伪**的。答案是否。

## 2. 答案

### 2.1 哪些因素决定薪资

**地理位置第一，且优势明显。** 最佳模型的置换重要性，在 3,000 条留出样本上测得：

| 排名 | 特征 | 打乱后 MAE 增量 |
|---:|---|---:|
| 1 | `region_name_Город Москва` | 0.0362 |
| 2 | `lng` | 0.0287 |
| 3 | `lat` | 0.0213 |
| 4 | `specialisation_Образование, наука` | 0.0145 |
| 5 | `svd_17`（一个文本成分） | 0.0131 |
| 6 | `schedule_Неполный рабочий день` | 0.0114 |

前三名里有两个是地理位置，而经纬度的排名**几乎与莫斯科指示变量本身一样高** —— 说明模型学到的是**地理上的薪资曲面**，而不是死记某一个城市。职业紧随其后。自由文本排第 5，而且是通过一个**学习到的成分**，不是任何单个具名技术。

这个排序本身就是结论：**岗位在哪、是什么类型的工作，压过了招聘广告要求什么。**

### 2.2 薪资能被预测到多准

**MAE 17,478 卢布，R² = 0.615**，测试集是训练窗口**之后**发布的岗位 —— 这是向前外推，不是内插。

| 模型 | MAE（卢布） | 占中位薪资 | R²（log） |
|---|---:|---:|---:|
| M0a 全局训练中位数 | 28,594 | 57.2% | −0.177 |
| M0b（地区 × 学历）格中位数 | 23,674 | 47.3% | 0.187 |
| M1 Ridge —— 稀疏，完整 TF-IDF | 17,966 | 35.9% | 0.592 |
| M1b Ridge —— 稠密设计 | 18,264 | 36.5% | 0.588 |
| **M2 梯度提升 —— 稠密** | **17,478** | **35.0%** | **0.615** |
| M3 神经网络（MLP）—— 稠密 | 17,945 | 35.9% | 0.595 |

最佳学习模型比最强基线改善 **26.2%**。

**这个数字怎么读。** 典型薪资的三分之一就是典型误差。模型能回答"这个 offer 在该地区该岗位的正常区间内吗"，不能回答"这个人到底该拿多少"。两个结果进一步限定了它：

- **莫斯科比其他地方难得多** —— MAE 41,657 卢布，是总体数字的两倍以上。首都的薪资离散度很大，而特征无法解释它。
- **预测系统性偏低约 13.8%**，原因见 §3.2。每个子群体都是如此。

次要的分类任务 —— 判断落在训练集薪资的哪个四分位 —— 准确率 57.5%，多数类基线 28.1%，宏 F1 为 0.550。**区间通常判断正确，具体数字很少正确。**

### 2.3 Q1 —— 结构化属性还是自由文本？

**文本挖掘是必要的，但薪资信号不住在那里。**

必要，是因为门户的结构化 `skills` 字段在 **77.4%** 的记录里为空。挖掘能从 36.7% 的记录中至少抽出一个技能，而结构化字段只有 24.1% —— **挖掘把覆盖率翻了一倍以上**。

但它的边际贡献有限且分散：

- 从文本的 128 维 SVD 压缩换成**完整 TF-IDF 词表**，只值 **1.6% 的 MAE**（M1b → M1）。
- 没有任何单个技能标记进入前六特征。文本是通过混合大量词项的**成分**发挥作用的。

所以诚实的答案是：**必须挖**，因为不挖就回答不了任何技能相关问题；但**不要指望它扛起预测**。那是地区和职业的活。

而且挖掘正是**最危险的缺陷**藏身之处 —— 一个朴素正则漏掉 43% 的 C++ 岗位（§3.1）。

### 2.4 Q2 —— IT 溢价有多大？

**几乎没有：+1.0%。**

原始对比看起来完全是另一回事。IT 中位数 50,000 卢布，对照组 45,000 —— **相差 11.1%**。但这不是受控对比：IT 岗位集中在莫斯科和圣彼得堡，且集中在更高学历的职业中。

把 `is_it` 指示变量放进 Ridge 回归，与地区、学历、职业、工作制和技能特征并列：

- `is_it` 的系数（对数尺度）：**+0.0103**
- 控制其他变量后的隐含薪资溢价：**+1.0%**

**所以原始差距几乎完全是构成差异，不是溢价。** 俄罗斯的 IT 薪资更高，主要因为**岗位在哪**和**是什么样的工作**，而不是"IT"这个标签本身值钱。

剩下的 1% 应理解为**偏相关**而非因果效应。控制变量仅限于本数据集测量到的内容，未测量的差异 —— 资历、合同类型、雇主性质 —— 依然存在。

### 2.5 Q3 —— 神经网络能自我辩护吗？

**不能。**

M2 与 M3 拿到**逐字节相同的输入矩阵**，唯一差别是模型类别：

| | MAE（卢布） | R²（log） |
|---|---:|---:|
| M2 梯度提升 | **17,478** | **0.615** |
| M3 MLP | 17,945 | 0.595 |

单个随机种子对神经网络不算证据，所以 MLP 用 **7 个种子**重训：R² = 0.6002 ± 0.0038（范围 0.595–0.605）。**M2 在全部 7 个种子上、两个指标上都胜出。**

这里诚实的表述很重要。梯度提升赢的幅度大致等于**网络自身的种子噪声宽度** —— 它不是以任何压倒性优势取胜。神经网络真正失败的，是提供**任何超出该噪声的收益**，同时付出可解释性和调参成本。

这个对比之所以有意义，全靠一个设计决策：早期版本给梯度提升喂 SVD 压缩文本，却给线性模型喂完整 TF-IDF 词表，结果梯度提升"输了"。**那是设计错误，不是发现**，§4 记录了它。

## 3. 限定这些答案的发现

这些不是边角料。**任何一个没被发现，都会产出一个看起来合理、实则错误的答案。**

### 3.1 三个静默失效的缺陷

**一个看起来像真数据的零值哨兵。** 门户用**字面值 `0`** 表示"薪资未指定"（原文 `"от 0"`），而不是留空。**179 条记录（0.91%）**。模型会从中认真学到"0 卢布月薪"，而且 `log(0)` 是 `-inf`。

**一个名不副实的字段。** `requirement.experience` 文档标注为整数、读起来像年数。**两者都不是。** 与自由文本交叉验证即可定论：`code = 0` 的广告要求**最高 35 年**经验，所以 `0` 不可能表示"无经验要求"；而 `code = 18` 出现在写着"от 1 года"的广告上。该列是未公开编码，已**从特征集中撤除** —— 经验在本数据源上根本不可用。

**一个吃掉 43% 技能的字母表陷阱。** 俄语广告经常用**西里尔字母 С**（U+0421）写 `C++`，与拉丁 C 视觉上完全相同，而 Python 的 `re.IGNORECASE` **不会**跨字母表折叠：

```python
re.search(r"c\+\+", "С++", re.I)   # -> None    静默漏掉
```

实测：137 个岗位只用拉丁写法，**102 个只用西里尔写法**，100 个两种混用 —— 漏检率 **102/239 = 43%**。看似显然的修法（归一化整段文本）会破坏正常俄语，因为 `с` 是俄语最常用的介词之一。我们改为让模式在真正发生混淆的少数位置接受两种字母。

### 3.2 预测系统性偏低，而且可以解释

**每一个**子群体的偏差都是负的 —— IT −7,792 卢布、对照组 −5,519、莫斯科 −21,776、圣彼得堡 −14,857 —— 平均约 **−6,900 卢布（中位数的 13.8%）**。

这不是某个子群体的假象，而是建模选择的后果。对 `log(salary)` 拟合平方误差估计的是**对数的**条件均值，指数还原后得到的是条件**中位数**，对右偏分布而言中位数低于均值。

标准修正是 **Duan smearing 估计量**，或在原尺度上指定损失函数。**本报告两者都未采用**，这一省略被**记录**而非掩盖：修了它会改变 §2 里的每一个数字，那是与"报告这些数字"不同的另一个决定。

### 3.3 一个通常不是区间的区间

21,941 条有薪资的记录里，自由文本 **100%** 是 `"от N"` 形式，所以文本从不携带上界；而 `salary_max` 等于 `salary_min` 的记录占全表 **38.5%**。上下界相等时区间不含信息量，于是 `salary_max` 置为缺失并给该行打标记。**只对 `salary_min` 建模。**

## 4. 这些答案建立在什么之上

简述如下；细节在 [README](../README.md) 与各阶段报告。

| | |
|---|---|
| **数据** | 22,387 条岗位记录，来自 Трудвсем 国家就业门户的官方开放数据 —— 12,656 条 IT + 9,731 条非 IT 对照，用 2,002 次请求覆盖 89 个地区 |
| **加工后** | 19,578 行 × 72 列，**10/10 质量门禁**通过；移除 446 条精确重复与 2,363 条近重复 |
| **切分** | 时序而非随机：2026-08-20 之前的 14,513 条训练，之后的 4,886 条测试。随机切分有两重无效性 —— 雇主会重复投放同一广告，且样本偏重新近发布 |
| **对比设计** | M1b、M2、M3 共享同一个逐字节相同的矩阵，所以对比检验的是**模型类别**而非特征工程 |
| **泄漏审查** | 每一列都携带显式决策。`salary_text` 字面上就是 `"от <目标值>"`，本会产出近乎完美且完全无意义的模型 |
| **验证** | 103 项测试、约 16 秒、不需要网络，由 CI 在 Python 3.12 和 3.13 上强制执行。抓出两个真 bug 并逼出一处接口改进 |

有两条关于**证据本身**的局限属于这里而非 §5，因为它们限定了上面每一个数字：

- **样本不是随机的。** 每个（关键词 × 地区）查询返回 API 自己的排序，且上限 100 条。所有数字描述的是这个样本，不是俄罗斯岗位总体。
- **未做超参数搜索。** 对比是在合理默认值上的**模型类别**之间，而非调优实例之间。

## 5. 什么会改变这些答案

1. **概率抽样。** 当前采集是便利样本，本报告没有任何内容能估计全国分布。
2. **可用的日期过滤。** API 没有能工作的日期过滤，所以时序切分是唯一对漂移的控制。
3. **经验数据。** 最有可能提升精度的字段，恰恰是那个被发现是未公开编码的字段。
4. **修正再变换偏差。** Duan smearing 会消除系统性 13.8% 的低估，并改变 MAE 数字。
5. **薪资上界。** 38.5% 的记录不可用，所以模型只用下界训练。
6. **门户偏向国企与蓝领岗位** —— IT 只占 52.2 万全国岗位中的少数。结论只在样本所描述的人群内成立。
